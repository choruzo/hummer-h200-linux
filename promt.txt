Quiero que hagas ingeniería inversa del software/controlador de la pantalla LCD del disipador:

NOX Hummer H-200 LCD

El objetivo final es sustituir en Ubuntu/Linux el software oficial de Windows "Hummer Digital" por una implementación nativa Linux.

IMPORTANTE:
- Estás trabajando directamente en la máquina Ubuntu donde está instalado físicamente el NOX Hummer H-200 LCD.
- El LCD está conectado al sistema mediante el mecanismo físico previsto por NOX, probablemente USB interno, pero NO debes asumir el protocolo ni la interfaz: debes descubrirlos.
- Disponemos del instalador oficial de Windows de Hummer Digital.
- Busca en el directorio actual, ~/Descargas, ~/Downloads y ubicaciones razonables archivos llamados de forma similar a:
  hummer_h-200_lcd-3cq2vmvz21.zip
  Hummer_DigitalSetup_H-200 LCD.exe
- Si no encuentras el instalador, indícalo claramente y continúa todo lo posible con el hardware conectado.
- Ubuntu es el sistema operativo objetivo.
- NO quiero depender de Windows ni Wine en la solución final.
- Preferencia inicial para la implementación: Python 3.
- Para acceso al dispositivo, preferir en este orden:
  1. hidapi / hidraw si es USB HID
  2. pyusb/libusb si es USB vendor-specific
  3. otra interfaz userspace si fuese necesaria
- NO desarrollar un módulo de kernel salvo que sea absolutamente imprescindible.

OBJETIVO FUNCIONAL

Crear un proyecto Linux, por ejemplo:

hummer-h200-linux/

que permita controlar la pantalla LCD del NOX Hummer H-200 desde Ubuntu.

Inicialmente quiero poder mostrar como mínimo:

- temperatura CPU
- temperatura GPU
- RPM si el hardware/pantalla lo admite
- Celsius/Fahrenheit si el protocolo lo permite

Después quiero dejar preparada la arquitectura para añadir:

- AMD Radeon AI PRO R9700:
  - temperatura
  - utilización
  - VRAM utilizada
- Intel Arc Pro B50:
  - temperatura

- métricas externas como tokens/s de llama.cpp

Pero NO inventes capacidades de la pantalla. Primero determina qué puede mostrar realmente el firmware del H-200.

==================================================
FASE 0 — SEGURIDAD Y REGLAS
==================================================

Antes de realizar ninguna escritura USB:

1. Identifica inequívocamente el dispositivo.
2. Obtén VID, PID, interfaces, endpoints y descriptores.
3. Comprueba si es HID, CDC, vendor-specific, etc.
4. No envíes paquetes arbitrarios.
5. No escribas en firmware.
6. No intentes actualizaciones de firmware.
7. No uses fuzzing USB.
8. No escribas datos aleatorios a endpoints.
9. No hagas pruebas que puedan modificar permanentemente el dispositivo.

La primera fase debe ser completamente pasiva.

Si necesitas sudo para alguna inspección, puedes utilizarlo, pero explica antes qué comando se va a ejecutar y por qué.

==================================================
FASE 1 — IDENTIFICACIÓN DEL HARDWARE
==================================================

Inspecciona el sistema.

Ejecuta y analiza, entre otros:

lsusb
lsusb -t
lsusb -v

Busca también:

ls -l /dev/hidraw*
ls -l /dev/ttyACM*
ls -l /dev/ttyUSB*

Para cada hidraw relevante:

udevadm info --attribute-walk --name=/dev/hidrawX

Inspecciona:

/sys/bus/usb/devices/
/sys/class/hidraw/
/sys/class/hwmon/

Relaciona cada dispositivo con su VID/PID.

Quiero que determines inequívocamente cuál corresponde al H-200 LCD.

Guarda la información importante en:

docs/hardware-identification.md

Incluye:

- VID
- PID
- fabricante
- product string
- serial si existe
- USB class
- interfaces
- endpoints
- HID report descriptor si existe
- tamaño máximo de report
- driver Linux asociado
- nodo /dev correspondiente

Si es HID, extrae y analiza el HID Report Descriptor.

Puedes utilizar herramientas como:

hid-recorder
usbhid-dump
hid-tools
libinput record

cuando tengan sentido.

No instales decenas de paquetes innecesariamente.
